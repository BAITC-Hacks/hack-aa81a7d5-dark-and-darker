# AI Sana Challenge Hub

Рабочий MVP для HackAlem AI: бизнес оформляет и публикует задачи, студенческие
команды предлагают решения, представитель бизнеса вручную принимает или
отклоняет предложения. Интерфейс на русском языке, с демонстрационными ролями.

## Технологии

- React 19, TypeScript, Vite; HTTP-запросы через `fetch`.
- Python 3.14.3, FastAPI, Pydantic v2, Uvicorn в локальном `.venv`.
- SQLite через стандартный модуль `sqlite3`, файл `backend/hackalem.db`.
- Локальные уточняющие вопросы и детерминированный рейтинг. Внешних AI API нет.
- Playwright — только для браузерных тестов, не нужен приложению во время работы.

Проект находится непосредственно в `/Users/altair/HackAlem`. Проверенная среда:
macOS, Node.js 22.22.1, npm 10.9.4, Python 3.14.3. Версии зависимостей
зафиксированы в `package-lock.json` и `backend/requirements.txt`.

## SQLite и тестовые данные

Таблицы и демонстрационные данные создаются автоматически при первом запуске
backend. Явная инициализация:

```sh
cd /Users/altair/HackAlem
npm run seed
```

Seed использует транзакцию и запись `demo-v1` в таблице `seed_runs`.
Повторный запуск не создаёт дубликаты и не перезаписывает пользовательские данные.

Исходные данные:

- 1 бизнес: Sana Business Lab, представитель Айдана Садыкова.
- 5 первоначальных черновиков.
- 5 опубликованных карточек: отзывы клиентов (100), спрос (75), доставка (55),
  заявки (30), энергопотребление (10).
- 5 команд с описаниями, навыками и контактами.
- 7 предложений: 3 на рассмотрении, 2 принятых, 2 отклонённых.

Все организации, контакты, количественные показатели и предложения в seed —
вымышленные демонстрационные данные. Конструктор новых задач использует только
введённый пользователем текст и не выдумывает недостающие сведения.

База сохраняется между перезапусками. Не удаляйте `backend/hackalem.db`, если
нужно сохранить работу. Для отдельной базы можно передать переменную окружения:

```sh
HACKALEM_DB_PATH=/absolute/path/demo.db npm run dev:backend
```

Каталог назначения должен существовать. Базы `*.db`, их служебные файлы,
`.venv`, `node_modules`, `.env` и результаты сборки исключены через `.gitignore`.

## Демонстрационные роли

Переключатель **Бизнес / Студент** находится в шапке.

**Бизнес:** свои задачи, создание и редактирование, подтверждение, публикация,
рейтинг и входящие предложения с ручным решением.

**Студент:** только опубликованные задачи в каталоге, профили команд, выбор
демонстрационной команды, отправка и просмотр её предложений.
Выбор команды доступен в профиле, форме предложения и разделе «Мои предложения».

Роль и выбранная команда могут запоминаться в localStorage. Все задачи, команды,
предложения и решения хранятся в SQLite и загружаются из API.

## Конструктор и рейтинг

1. Название и первоначальное описание создают черновик.
2. Семь локальных вопросов помогают уточнить детали. Ответы необязательны.
3. Карточка собирается из ответов без добавления фактов.
4. Любое поле можно отредактировать, затем нажать «Подтвердить карточку».

Ответы сохраняются в SQLite при переходе вперёд и назад. Кнопка «Сохранить и
выйти» сохраняет текущие изменения. Закрытие вкладки с несохранёнными изменениями
вызывает предупреждение браузера. Перед переходом в другой раздел сохраните форму.

Рейтинг рассчитывает backend:

| Поле | Баллы |
| --- | ---: |
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |

Поле после удаления крайних пробелов непустое — начисляется весь вес, иначе 0.
Название и краткое описание не добавляют баллов. Это оценка полноты заполнения,
а не автоматическая проверка смысла или достоверности текста.

Уровни: 0–39 «Черновик», 40–69 «Рабочая», 70–89 «Готовая», 90–100 «Приоритетная».
Уровень «Черновик» — характеристика рейтинга; статус публикации хранится отдельно.

**Рейтинг не блокирует публикацию, в том числе при 0 баллов.** Обязательно лишь
ручное подтверждение текущей версии. Сохранение содержательных изменений
сбрасывает подтверждение и переводит опубликованную задачу обратно в черновик.
После повторного подтверждения её можно опубликовать снова. Уже отправленные
предложения сохраняются. Сохранение тех же значений не сбрасывает подтверждение.

Команда может отправить одно предложение на задачу. Новое предложение получает
статус `pending`. Только человек принимает или отклоняет его. Обработанное
предложение нельзя обработать повторно или вернуть в `pending`; API возвращает
409. Для ожидающего предложения запрос `pending` оставляет его без изменения.
Принятие одного предложения не отклоняет другие автоматически.

Провайдер вопросов выделен в `backend/app/readiness.py::generate_questions`.
Его можно позднее заменить вызовом AI, сохранив формат API. Сейчас запросов к
OpenAI, ключей и внешней генерации нет.

## API

Полные схемы запросов доступны в `/docs`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Доступность сервера |
| GET | `/api/questions` | Локальные вопросы и веса полей |
| GET | `/api/tasks` | Каталог с фильтрами, поиском и сортировкой |
| GET | `/api/tasks/{id}` | Карточка задачи |
| POST | `/api/tasks` | Создание черновика, HTTP 201 |
| PATCH | `/api/tasks/{id}` | Изменение полей карточки |
| POST | `/api/tasks/{id}/confirm` | Подтверждение текущей версии |
| POST | `/api/tasks/{id}/publish` | Публикация подтверждённой карточки |
| GET | `/api/tasks/{id}/readiness` | Баллы, уровень и рекомендации |
| GET | `/api/teams` | Список команд |
| GET | `/api/teams/{id}` | Профиль команды |
| POST | `/api/tasks/{id}/proposals` | Предложение команды, HTTP 201 |
| GET | `/api/tasks/{id}/proposals` | Предложения по задаче бизнеса |
| GET | `/api/teams/{id}/proposals` | Предложения выбранной команды |
| GET | `/api/proposals` | Все предложения демонстрационному бизнесу |
| PATCH | `/api/proposals/{id}/status` | Ручное решение по предложению |

Параметры `/api/tasks`:

- `status`: `draft` или `published`.
- `readiness_level`: `Черновик`, `Рабочая`, `Готовая`, `Приоритетная`.
- `sort`: `newest`, `oldest`, `score_desc`, `score_asc`.
- `search`: поиск по названию и описанию без учёта регистра, включая русский.
- `business_id`: фильтр по владельцу; демонстрационный бизнес имеет ID 1.

Ошибки: 404 — объект не найден; 422 — неверные входные данные; 409 — конфликт
состояния, неподтверждённая публикация, повторное предложение или решение;
403 — изменение чужой задачи. Изменяющие запросы возвращают актуальный объект.

## Сценарий демонстрации

1. Откройте приложение в роли **Бизнес**. Посмотрите черновики и опубликованные задачи.
2. Нажмите **Создать задачу**, введите название и описание, перейдите дальше.
3. Ответьте на несколько вопросов; часть полей оставьте пустыми. Проверьте, что
   ответы сохраняются при переходах «Назад» / «Далее».
4. Просмотрите структуру, перейдите к правкам, измените любое поле и подтвердите.
5. Посмотрите баллы и рекомендации. Опубликуйте задачу даже при низком рейтинге.
6. При желании отредактируйте её: подтверждение сбросится, публикацию понадобится повторить.
7. Переключитесь на **Студент**, найдите задачу в каталоге. Попробуйте поиск,
   фильтры и сортировку. Посмотрите профили команд.
8. Откройте задачу, выберите команду, заполните сообщение и решение, отправьте
   предложение. Убедитесь в статусе «На рассмотрении» в «Мои предложения».
9. Переключитесь на **Бизнес**, откройте «Предложения», примите или отклоните его.
10. Вернитесь к студенту, проверьте новый статус. Перезапустите backend — данные сохранятся.

## Проверки

```sh
cd /Users/altair/HackAlem
npm run build
npm run test:backend
```

Backend-тесты используют стандартный `unittest`, отдельную временную SQLite-базу
и настоящий HTTP-сервер на свободном порту. Они проверяют 128 комбинаций рейтинга,
seed, валидацию, поиск и сортировку, публикацию с 0 баллов, сброс подтверждения,
предложения и сохранность данных после остановки и повторного запуска сервера.

Для браузерных тестов один раз установите тестовый браузер:

```sh
npx playwright install chromium
npm run test:e2e
```

E2E-тесты автоматически поднимают отдельные серверы на портах 5174 и 8001,
создают временную базу и удаляют её после проверки. Демонстрационная база
`backend/hackalem.db` не меняется. Проверяются полный сценарий, нулевой рейтинг,
фильтры, команды, принятие и отклонение, мобильный экран и восстановление после
ошибки сети. Скриншоты и диагностические данные находятся в `test-results/`.

Локальный просмотр production-сборки:

```sh
npm run build
npm run preview
```

Откройте http://127.0.0.1:4173. Backend должен быть запущен отдельно.

## Границы MVP

Регистрации и авторизации по заданию нет. Переключатель ролей управляет
демонстрационным интерфейсом, а не защищает API. Сервер рассчитан на локальную
демонстрацию с одним бизнесом; для публичного развёртывания нужны реальные
пользователи, авторизация и проверка доступа к данным.

Нет внешнего AI, загрузки файлов, автоматического назначения исполнителей,
отправки писем, пагинации и совместного редактирования с разрешением конфликтов.
Контакты — текст. Проверка качества описания остаётся за человеком.
